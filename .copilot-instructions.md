# Copilot Instructions for Screeps TNF

This document provides comprehensive guidance for AI assistants working on the screeps-tnf codebase. Follow these instructions to make effective, safe changes while maintaining code quality and project standards.

## Project Overview

**Screeps TNF** is a personal Screeps AI implementation built on the TypeScript starter template. **Screeps** is a MMO strategy sandbox game for programmers where you control your colony by writing real JavaScript/TypeScript code.

This repository contains:
- A customized Screeps AI with basic room management logic
- TypeScript development environment with proper tooling
- Rollup bundling for deployment to Screeps servers
- Testing framework with Mocha and Chai
- Source map support for debugging
- ESLint and Prettier for code quality

### Current AI Features
- Basic room scanning and ownership detection
- Spawn management and creep creation
- Automatic cleanup of dead creep memory
- Username-specific room control logic (currently set to "ricane")

## Key Files and Their Purpose

### `src/main.ts`
- **Primary file**: Contains the main game loop function exported as `loop`
- **Critical**: Must export a `loop` function that Screeps calls every game tick
- **Pattern**: Wrapped with `ErrorMapper.wrapLoop()` for source-mapped error handling
- **Current logic**: Basic room scanning, spawn management, and creep cleanup

### `src/utils/ErrorMapper.ts`
- **Purpose**: Maps bundled JavaScript errors back to TypeScript source locations
- **Warning**: High CPU cost on first use after reset (>30 CPU)
- **Critical**: Do not modify unless you understand source map implications

## Coding Conventions and Patterns

### Code Style Configuration
- **ESLint**: Configured with TypeScript, Prettier, and import rules
- **Prettier**: 120 char width, 2 spaces, semicolons, double quotes
- **Key Rules**: 
  - Explicit member accessibility required (`public`, `private`)
  - camelCase naming convention
  - No `any` types where possible
  - One class per file maximum
  - Sort imports (warning level)

### TypeScript Patterns
```typescript
// Global type extensions in main.ts
declare global {
  interface Memory {
    // Custom memory extensions
  }
  interface CreepMemory {
    role: string;
    room: string;
    working: boolean;
  }
}

// Main loop pattern
export const loop = ErrorMapper.wrapLoop(() => {
  // Game logic here
  console.log(`Current game tick is ${Game.time}`);
  
  // Always clean up dead creeps
  for (const name in Memory.creeps) {
    if (!(name in Game.creeps)) {
      delete Memory.creeps[name];
    }
  }
});
```

### Screeps API Patterns

for (var roomid in Game.rooms) {

### Current AI Architecture
The AI currently follows a simple pattern:
1. **Room Scanning**: Iterate through all visible rooms
2. **Ownership Check**: Identify owned rooms by username
3. **Spawn Management**: Find spawns and attempt to create basic workers
4. **Memory Cleanup**: Remove memory of dead creeps

### Username Configuration
**Important**: The AI is currently hardcoded to username "ricane". When making changes:
- Consider making this configurable
- Update the username check when deploying to different accounts
- Be aware this affects room ownership detection

### Error Handling
- Always use `ErrorMapper.wrapLoop()` for the main loop
- Use try-catch blocks for risky operations
- Log meaningful messages with `console.log()`

## Safety Guidelines for Code Changes

### Critical "Do Not Touch" Areas
1. **ErrorMapper.ts**: Complex source map handling - modify only if essential
2. **Global type declarations**: Breaking changes affect entire codebase
3. **Main loop export**: Must always export a function named `loop`

### Safe Change Areas
1. **Game logic inside loop function**: Core gameplay code
2. **Utility functions**: Add new utilities in `src/utils/`
3. **Memory interfaces**: Extend but don't break existing properties
4. **Tests**: Add new tests, modify existing ones carefully

### Change Validation Checklist
- [ ] Does `npm run test` pass?
- [ ] Does the main loop still export a `loop` function?
- [ ] Are global type extensions maintained?
- [ ] Does the code follow existing patterns?
- [ ] Have you tested the change in context?

## Gotchas and Special Considerations

### Screeps-Specific Issues
1. **CPU Limits**: Every operation costs CPU - optimize for efficiency
2. **Memory Persistence**: Memory persists between ticks, Game objects don't
3. **Tick-Based Execution**: Code runs once per game tick, plan accordingly
4. **Constants**: Use Screeps constants (WORK, CARRY, MOVE, etc.)

### Development Environment Issues
1. **Node Version**: Project targets Node 10.x/12.x but works on newer versions
2. **Build Errors**: Some build issues exist but don't affect core functionality
3. **ESLint Config**: May have configuration issues with newer versions
4. **Source Maps**: Only work on live servers, not in simulator

### Performance Considerations
1. **ErrorMapper**: First call after reset is expensive (>30 CPU)
2. **Memory Access**: Cache frequently accessed Memory objects
3. **Find Operations**: Use sparingly, cache results when possible
4. **Console Logging**: Minimize in production code
